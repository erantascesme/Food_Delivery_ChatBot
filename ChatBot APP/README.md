# ChatBot APP: Directory Structure & Codebase

This folder contains the complete codebase for the web-based conversational food-delivery recommender system. It is built using Python, Flask, LangChain, and Google's Gemini API, and is configured for deployment on AWS Elastic Beanstalk.

Below is an overview of the directory structure and the specific role of each file and folder.

## 📂 Folders

* **`data/`**
Contains the synthetic JSON datasets that simulate the food-delivery ecosystem. This includes `restaurants.json`, `dishes.json`, `customers.json`, `deliverers.json`, and `orders.json`. It also includes a `profiles/` subdirectory where dynamic user constraints are saved during chat sessions.
* **`faiss_index/`**
The local vector database directory generated by Facebook AI Similarity Search (FAISS). It stores the high-dimensional embeddings of the restaurant and dish data, enabling the application to perform fast semantic similarity searches.
* **`static/`**
Contains the static web assets served by Flask to the client's browser. This typically includes the `style.css` file for styling, the `script.js` file for frontend interactivity (handling the chat UI and order flow), and any background images.
* **`templates/`**
Holds the HTML template files rendered by Flask. This includes the main interface (`chat.html`) and user authentication pages (such as `login.html` and `signup.html`).

## 📄 Files

* **`Procfile`**
A configuration file specifically used for cloud deployment (AWS Elastic Beanstalk). It instructs the server on how to boot the application, typically defining the Gunicorn web server command to run the Flask app.
* **`application.py`**
The main entry point for the Flask web application. It handles the HTTP routing, renders the frontend HTML templates, manages user sessions, and serves as the bridge between the frontend chat interface and the backend AI logic.
* **`chatbot_logic.py`**
The core reasoning engine of the application. It establishes the LangChain pipeline, connects to the Google Gemini API, interacts with the FAISS vector database, and manages the Dynamic Preference Engine to update user constraints in real-time.
* **`ingest.py`**
A standalone data preparation script. When run, it reads the raw JSON catalog data from the `data/` folder, chunks it, converts it into vector embeddings using the Gemini embedding model, and saves the resulting database into the `faiss_index/` folder.
* **`requirements.txt`**
The dependency file listing all the Python libraries required to run the application (e.g., `flask`, `langchain`, `langchain-google-genai`, `faiss-cpu`, `pydantic`). This is used to install the correct environment locally and on the AWS server.
